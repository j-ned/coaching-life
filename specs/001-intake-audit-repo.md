### Vue d'ensemble

Coaching Life est la vitrine d'une coach indépendante, avec un tableau de bord d'administration : 5 pages publiques (accueil + 4 pages de service), prise de rendez-vous, formulaire de contact, et un tableau de bord admin (statistiques Chart.js, rendez-vous et disponibilités, messages, édition du contenu des pages et de l'accueil). Le front est en **Angular 22.1.4**, entièrement standalone, **zoneless** (pas de `zone.js` dans les dépendances, c'est le défaut v22), `OnPush` partout, API signals (`input()`/`output()`/`viewChild()`/`computed`), control flow natif à 100 %, Tailwind 4. L'organisation est hexagonale par feature (`features/<x>/{domain/{models,gateways,use-cases},infra}`), avec des ports abstraits branchés sur des adaptateurs HTTP dans `app.config.ts`. Le backend Hono + Drizzle + Zod (`backend/`, workspace pnpm) expose `/api/*` **et sert lui-même les fichiers statiques** Angular : le Dockerfile ne copie que `dist/coaching-life/browser` ; le serveur Express `src/server.ts` n'est **jamais déployé**. Il n'y a pas de CI, et aucun linter.

**Mode de rendu (fait structurant)** : **hybride SSG + CSR**. `app.routes.server.ts` prérend 5 routes (`''`, `life-coach`, `personal-development`, `equine-coaching`, `neuroatypical-parents`) via `RenderMode.Prerender` (constaté au build : « Prerendered 5 static routes »), avec `RenderMode.Client` pour `dashboard/**` et `**`. L'hydratation est active (`provideClientHydration(withEventReplay(), withNoIncrementalHydration())`, attributs `ngh` présents dans l'artefact). Le `<head>` (titre, description, canonical, OG) est bien émis au prerender par `core/seo/seo.ts` : vérifié dans `dist/coaching-life/browser/*/index.html`. En revanche, **tout le contenu éditable** (accueil, pages de service) est chargé en `afterNextRender`, donc uniquement côté navigateur. Le HTML prérendu ne contient que les valeurs par défaut codées en dur, sans aucune image (`imageUrl: ''` dans `default-content.ts`). Les points chauds (volume × fréquence de modification) sont les composants du tableau de bord (`dashboard-appointments` 684 lignes, `dashboard-content-edit` et `dashboard-content-home` 480 lignes chacun) ainsi que `home.ts` et `main-layout.ts`. La suite de tests (90 tests) couvre **uniquement** les gateways, les adaptateurs et les cas d'usage : aucun composant n'est testé.

### Synthèse (≤ 10 points, classés par impact)

1. F001 : l'API publique de réservation n'applique **aucune règle métier côté serveur** (chevauchement, jour désactivé, date passée, horaires, durée) et envoie un email de confirmation à n'importe quelle adresse saisie.
2. F004 : le contenu édité dans le CMS n'atteint **jamais** le HTML prérendu. Les robots voient les textes par défaut, sans images, et les visiteurs voient le contenu changer après l'hydratation.
3. F002 / F003 : les gateways HTTP avalent les erreurs. Un mauvais mot de passe ferme la modale et renvoie silencieusement à l'accueil ; une session expirée affiche « 0 rendez-vous » au lieu d'une erreur.
4. F005 : Chart.js complet (tous les contrôleurs) est embarqué dans le bundle initial **du site public** pour un seul graphique du tableau de bord.
5. F006 / F007 : aucun test de composant et aucune CI. Les bugs F002 et F003, typiquement interceptés par un test de composant, sont passés.
6. F008 / F010 : vulnérabilités actives (nodemailer < 10.0.2 en runtime backend ; `@angular/router` et `platform-server` 22.1.4).
7. F012 / F011 : modernisation du rendu. Activer l'hydratation incrémentale (avis clients absents du prerender) et trancher entre `outputMode: "static"` et un vrai déploiement SSR.
8. F017 / F018 : modernisation Angular 22. Signal Forms (5 formulaires Reactive) et `resource()`/`httpResource()` à la place de `effect()` asynchrones sujets aux réponses obsolètes.
9. F023 à F026 : accessibilité. Aucune région live (`aria-live`, `role="status"`) ni `aria-invalid` dans tout `src/app` ; boutons de soumission désactivés ; `role="grid"` incorrect ; raccourci Ctrl+L détourné.
10. F009 / F015 / F016 : dette de structure. Composant « god » du tableau de bord, 4 pages de service quasi identiques, flux d'upload dupliqué.
